# Books API

A simple RESTful API for managing a collection of books, built with Express.js. It supports full CRUD (Create, Read, Update, Delete) operations and stores data in memory.

Built for **ITPE101 – Integrative Programming & Technology**, Laboratory Activity: Building, Testing, and Deploying a RESTful API.

## Technologies Used

- Node.js
- Express.js 4
- Postman (API testing)
- Git & GitHub (version control)
- Render (deployment)

## Installation and Local Execution

Requirements: [Node.js](https://nodejs.org/) 18 or newer.

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
cd YOUR_REPOSITORY_NAME
npm install
npm start
```

The server runs at `http://localhost:3000` (or on the port given by the `PORT` environment variable). You should see `Server is running on port 3000`.

## Book Fields

| Field    | Type    | Required | Rules                                        |
|----------|---------|----------|----------------------------------------------|
| `id`     | number  | auto     | Generated by the server, cannot be changed   |
| `title`  | string  | yes      | Non-empty                                    |
| `author` | string  | yes      | Non-empty                                    |
| `year`   | integer | yes      | Between 1 and the current year               |
| `genre`  | string  | no       | Non-empty if provided (default: Uncategorized) |

## Endpoints

| Method | Route            | Purpose                                         | Success | Error codes   |
|--------|------------------|-------------------------------------------------|---------|---------------|
| GET    | `/`              | API status message                              | 200     | –             |
| GET    | `/api/books`     | Retrieve all books (optional `?author=` filter) | 200     | –             |
| GET    | `/api/books/:id` | Retrieve one book                               | 200     | 400, 404      |
| POST   | `/api/books`     | Create a book                                   | 201     | 400           |
| PUT    | `/api/books/:id` | Replace a book (all required fields needed)     | 200     | 400, 404      |
| PATCH  | `/api/books/:id` | Update one or more fields of a book             | 200     | 400, 404      |
| DELETE | `/api/books/:id` | Delete a book                                   | 200     | 400, 404      |

Status codes: `200 OK`, `201 Created`, `400 Bad Request` (invalid ID, validation failure or malformed JSON), `404 Not Found`.

## Example Request Body (Create a Book)

`POST /api/books` with header `Content-Type: application/json`:

```json
{
  "title": "Introduction to Algorithms",
  "author": "Thomas H. Cormen",
  "year": 2009,
  "genre": "Computer Science"
}
```

Example response (`201 Created`):

```json
{
  "id": 4,
  "title": "Introduction to Algorithms",
  "author": "Thomas H. Cormen",
  "year": 2009,
  "genre": "Computer Science"
}
```

Example error response (`400 Bad Request`) for `{ "title": "" }`:

```json
{
  "error": "Validation failed.",
  "details": [
    "title is required and must be a non-empty string.",
    "author is required and must be a non-empty string.",
    "year is required and must be an integer between 1 and 2026."
  ]
}
```

## Testing

Import `postman/Books-API.postman_collection.json` into Postman. The collection has a `baseUrl` variable: use `http://localhost:3000` locally, or change it to the Render URL for the deployed API. It includes successful and unsuccessful requests (404, 400 validation errors, invalid ID, malformed JSON).

## Known Limitations

- Data is stored in an in-memory array, so it is temporary. All changes are lost when the server restarts or the Render instance is replaced, and the API resets to three sample books.
- No authentication or authorization.
- No pagination.
- On Render's free tier, the service sleeps after a period of inactivity, so the first request may take about a minute.
